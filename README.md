# Трекінг людини: віртуальна поворотна камера

Браузерне демо системи супроводу людини поворотною камерою (pan/tilt). Камера знаходить людину в кадрі, а регулятор повертає платформу так, щоб людина залишалася в центрі поля зору.

**Демо:** https://qitech.github.io/person-tracking-gimbal/ · **Відео:** _посилання на відео-демо_

Працює повністю в браузері, без сервера. Потрібні камера і Chrome або Edge.

## Що видно на екрані

- **Повний кадр камери.** Скелет людини, точка наведення (червона), рамка поля зору поворотної камери (помаранчева) і лінія похибки між центром рамки та ціллю. Клік по іншій людині робить її ціллю.
- **Вигляд з поворотної камери.** Те, що «бачить» камера на платформі, з перехрестям і станом системи: «Пошук», «Супровід», «Ціль втрачено», «Повернення».
- **3D-модель платформи.** Повертається на ті самі кути, що й камера. Обертається мишкою.
- **Графіки.** Похибка наведення і кути pan/tilt за останні 10 с.
- **Керування.** Автоматичний і ручний режим (повзунки або стрілки), пресети регулятора, розширені налаштування.

Щоб побачити, як налаштування регулятора впливає на поведінку, перемкніть пресет на «Повільний» (ціль помітно «втікає» від центру) або «Розгойдується» (перерегулювання й коливання).

## Як це працює

```
камера → детектор пози → трекер цілі → похибка (°)
       → PID (pan, tilt) → GimbalDriver → модель сервоприводів
       → нові кути → вікно поля зору зсувається → наступний кадр
```

1. **Детекція.** MediaPipe Pose Landmarker (lite) знаходить до трьох людей і 33 ключові точки кожної. Точка наведення — центр торсу (або голова, перемикається в налаштуваннях).
2. **Трекер.** Обирає людину, найближчу до центру поля зору, і тримає саме її між кадрами. Якщо ціль зникла, платформа чекає 1,5 с, а потім плавно повертається в нульову позицію.
3. **Регулятор.** PID на кожну вісь видає команду кутової швидкості. Є мертва зона (щоб камера не тремтіла), обмеження виходу, захист від накопичення інтегральної помилки, похідна за вимірюванням.
4. **Модель сервоприводу.** Затримка команди, обмеження прискорення і швидкості, жорсткі межі кутів. Рахується фіксованим кроком 200 Гц незалежно від частоти кадрів.

### Віртуальна поворотна камера

Камера ноутбука нерухома, тому повний кадр використовується як «світ», а поворотна камера — як вужче вікно всередині нього (pinhole-модель, поле зору 70° для камери ноутбука і 35° для віртуальної). Кути pan/tilt зсувають це вікно, і регулятор утримує людину в його центрі. Тобто контур керування замкнений, як у реальній системі: погано налаштований регулятор тут справді розгойдується.

Діапазон повороту обмежений тим, щоб вікно не виходило за кадр: для 16:9 це ±21° по горизонталі і ±12° по вертикалі.

### Спрощення симуляції

- Поворот моделюється зсувом вікна без перспективних спотворень. Для невеликих кутів це прийнятно.
- Кут цілі вимірюється в нерухомій системі координат кадру, тоді як реальна камера на платформі бачить ціль відносно власного положення в момент знімання. Запізнення реальної системи моделюється затримкою команди (за замовчуванням 60 мс).

## Перевірені характеристики

Тест замкненого контуру (стрибок цілі на 10°, затримка 60 мс, детекція 30 Гц):

| Пресет | Kp / Ki / Kd | Перерегулювання | Час встановлення (±1°) |
|---|---|---|---|
| Добре налаштований | 6 / 1 / 0,3 | немає | 0,4 с |
| Повільний | 1 / 0 / 0 | — | 2,2 с |
| Розгойдується | 14 / 0 / 0 | 76% | 1,4 с |

При русі цілі по синусоїді (амплітуда 10°, 0,2 Гц) середньоквадратична похибка пресету «Добре налаштований» — 1,64°. Після зупинки цілі платформа повністю зупиняється в межах мертвої зони, без «полювання» навколо точки.

## Архітектура

| Модуль | Що робить |
|---|---|
| `src/camera` | Доступ до камери |
| `src/detection` | Обгортка над Pose Landmarker, точки наведення |
| `src/tracking` | Вибір і утримання цілі, стани втрати й повернення |
| `src/geometry` | Модель камери: пікселі ↔ кути, вікно поля зору, межі |
| `src/control` | PID, утримання позиції, пресети |
| `src/gimbal` | Інтерфейс `GimbalDriver`, модель сервоприводу, симуляційний драйвер |
| `src/app` | Головний цикл і контролер режимів |
| `src/ui` | Відео з оверлеєм, вигляд з камери, 3D-модель, графіки, панель керування |

Логіка (`geometry`, `control`, `gimbal`, `tracking`, `app/controller`) не залежить від браузера і покрита тестами Vitest, включно з тестом замкненого контуру для кожного пресету.

Регулятор працює тільки з інтерфейсом `GimbalDriver`. Зараз за ним стоїть симуляція, а реальне залізо підключається окремою реалізацією того самого інтерфейсу без змін в іншому коді.

## Запуск локально

```bash
npm ci
npm run dev
```

Відкрийте адресу, яку покаже Vite, у Chrome і дозвольте доступ до камери.

```bash
npm test        # тести логіки
npm run build   # збірка в dist/
```

Файли моделі й WASM MediaPipe вже лежать у `public/`. Оновити їх можна командою `npm run fetch-assets`.

## Підключення реального заліза

Наступний крок — ESP32 з драйвером PCA9685 (або прямим PWM) і двома сервоприводами (pan, tilt). Зв'язок через USB-serial (Web Serial у Chrome), 115200 бод, текстові рядки, що закінчуються `\n`.

**Хост → ESP32:**
- `A <pan> <tilt>` — абсолютні цільові кути в градусах, точність 0,1, частота ~50 Гц
- `H` — повернення в нуль
- `?` — запит стану

**ESP32 → хост:**
- `S <pan> <tilt>` — поточні кути (у відповідь на `?` і періодично)
- `E <code>` — помилка

**Безпека:** якщо команди не надходять 500 мс, ESP32 тримає поточну позицію. Межі кутів дублюються в прошивці.

`SerialGimbalDriver` інтегрує команду швидкості в цільовий кут і надсилає `A` з частотою 50 Гц. Решта коду не змінюється.

## Плани розвитку

- Реальна платформа на ESP32 і сервоприводах (протокол вище).
- Стабілізація за IMU для платформи на рухомій основі.
- Супровід кількох цілей і перемикання між ними за правилами.
- Тепловізійна або нічна камера.
- Детекція на edge-пристрої (Raspberry Pi, Jetson) замість браузера.
