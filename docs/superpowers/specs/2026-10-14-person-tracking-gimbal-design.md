# Трекінг людини з віртуальною поворотною камерою: специфікація

Дата: 2026-10-14
Статус: погоджено в обговоренні, очікує фінального перегляду

## 1. Контекст і мета

Тестове завдання, сформульоване усно: «трекінг людини, можливо, сервоприводи». Формулювання неформальне, тому рішення має бути наочним, робочим і показувати розуміння предметної області: керування, механіки й комп'ютерного зору.

**Критерій успіху:** людина відкриває посилання, стає перед камерою і бачить, як віртуальна поворотна камера стежить за нею, утримуючи її в центрі. Графіки показують стабільну роботу регулятора, а README пояснює, що до реального заліза лишився один крок.

**Обмеження:**
- Термін 2–3 дні, активна розробка з ШІ.
- Працює повністю в браузері, без бекенда.
- Реальне залізо не реалізуємо. Проєктуємо інтерфейс і описуємо протокол як наступний крок.
- Інтерфейс і README українською, код і коментарі англійською.

**Поза межами (non-goals):**
- Драйвер реального заліза (ESP32 / Web Serial), лише опис протоколу.
- Одночасний супровід кількох цілей.
- Бекенд, збереження даних, запис відео.
- Мобільна версія. Цільовий екран — десктоп від 1280px. На вужчих екранах панелі просто складаються вертикально, без окремого дизайну.

## 2. Технології

- **TypeScript + Vite**, без UI-фреймворку.
- **@mediapipe/tasks-vision**, модель **Pose Landmarker (lite)**, режим `VIDEO`, `numPoses: 3`, делегат GPU з відкатом на CPU. WASM-файли й файл моделі (`pose_landmarker_lite.task`) лежать у проєкті (`public/`), щоб демо не залежало від сторонніх CDN.
- **Three.js** для 3D-моделі платформи.
- **uPlot** для графіків реального часу.
- **Vitest** для тестів логіки.
- **GitHub Pages** + GitHub Actions для деплою.
- Основний браузер — Chrome/Edge (останні версії). Safari/Firefox підтримуються за можливості.

## 3. Архітектура

### 3.1 Контур керування

```
камера → детектор пози → трекер цілі → похибка (°)
       → PID (pan, tilt) → GimbalDriver → модель сервоприводів
       → нові кути → вікно поля зору зсувається → наступний кадр
```

### 3.2 Модулі

| Модуль | Відповідальність | Залежить від браузера |
|---|---|---|
| `camera` | `getUserMedia`, видає `HTMLVideoElement` і розміри кадру | так |
| `detection` | Обгортка над Pose Landmarker: кадр → `Person[]` (ключові точки, рамка, точки наведення) | так |
| `tracking` | Вибір цілі, утримання між кадрами, машина станів втрати цілі | ні |
| `geometry` | Модель камери (pinhole): пікселі ↔ кути, розрахунок вікна поля зору | ні |
| `control` | PID на одну вісь, пресети | ні |
| `gimbal` | Інтерфейс `GimbalDriver`, модель сервоприводу, `SimGimbalDriver` | ні |
| `app` | Головний цикл: зв'язує модулі, тримає стан застосунку | так |
| `ui` | Оверлей, вигляд з камери, 3D-модель, графіки, панель керування, статуси | так |

Модулі `tracking`, `geometry`, `control` і `gimbal` — чистий TypeScript без DOM, повністю покриті тестами.

### 3.4 Ключові інтерфейси

```ts
interface Person {
  keypoints: { x: number; y: number; visibility: number }[]; // пікселі кадру
  bbox: { x: number; y: number; w: number; h: number };
  aim: { torso: Point | null; head: Point | null };
}

interface GimbalState {
  pan: number; tilt: number;          // градуси
  panVel: number; tiltVel: number;    // °/с
}

interface GimbalLimits {
  panMin: number; panMax: number; tiltMin: number; tiltMax: number;
  maxVel: number; maxAccel: number;
}

interface GimbalDriver {
  readonly limits: GimbalLimits;
  setVelocityCommand(pan: number, tilt: number): void; // °/с
  getState(): GimbalState;
  update(dtSeconds: number): void; // для симуляції; у реального драйвера — no-op
  home(): void;
}
```

Регулятор і решта застосунку працюють лише з `GimbalDriver`. Майбутній `SerialGimbalDriver` (ESP32 через Web Serial) реалізує той самий інтерфейс без змін в іншому коді.

## 4. Геометрія віртуальної камери

- Фізична камера описується pinhole-моделлю. Горизонтальне поле зору `physHfov` за замовчуванням 70° (налаштовується). Фокусна відстань у пікселях: `f = (W/2) / tan(physHfov/2)`.
- Піксель → кут: `angleX = atan((x - W/2) / f)`, `angleY = -atan((y - H/2) / f)` (tilt додатний угору).
- Віртуальна камера має поле зору `virtHfov`, за замовчуванням 35° (налаштовується, «зум»), і те саме співвідношення сторін, що й кадр.
- Вікно поля зору: центр `(W/2 + f·tan(pan), H/2 − f·tan(tilt))`, ширина `2·f·tan(virtHfov/2)`, висота — за співвідношенням сторін.
- Межі pan/tilt рахуються так, щоб вікно повністю лишалося в кадрі. Для 16:9, 70°/35° це приблизно pan ±17°, tilt ±11°. Ці межі й записуються в `GimbalLimits`.
- Спрощення: обертання вікна моделюється як зсув без перспективних спотворень. Для невеликих кутів це прийнятно, у README згадуємо.
- На 3D-моделі показуємо ті самі кути pan/tilt у градусах.

## 5. Детекція і точка наведення

- Pose Landmarker повертає до 3 поз. Ключова точка вважається видимою, якщо `visibility ≥ 0.5`.
- **Торс:** середнє плечей (11, 12) і стегон (23, 24) з видимих. Якщо стегна не видно, беремо плечі, зсунуті вниз на 0,25 ширини плечей. Якщо не видно жодного плеча, торсу немає.
- **Голова:** ніс (0), якщо він видимий, інакше середнє очей (2, 5).
- Обрана точка наведення (торс або голова, перемикається в UI) згладжується експоненційним фільтром (`alpha` за замовчуванням 0,5).
- Якщо обраної точки немає, а інша є, використовуємо іншу.

## 6. Трекер цілі

Стани: `searching` → `tracking` → `lost` → `returning` → `searching`.

- **Захоплення (`searching`):** з усіх людей з точкою наведення обирається найближча до центру вікна поля зору.
- **Утримання (`tracking`):** на кожному кадрі ціль зіставляється з найближчою людиною в межах воріт (gate) 15% ширини кадру від попередньої позиції. Якщо збігу немає, переходимо в `lost`.
- **Втрата (`lost`):** платформа тримає позицію (нульова команда швидкості). Якщо ціль з'являється в межах воріт (з урахуванням останньої позиції), повертаємося в `tracking`. Після 1,5 с переходимо в `returning`.
- **Повернення (`returning`):** платформа плавно їде в (0, 0) зі швидкістю до 30°/с. Будь-яка людина в кадрі запускає захоплення.
- **Ручний вибір:** клік по людині на повному кадрі робить її ціллю (перехід у `tracking`).
- Трекер не залежить від DOM: на вхід `Person[]`, час і центр вікна, на вихід стан і точка наведення.

## 7. Керування

### 7.1 Похибка

`error = targetAngle − currentAngle` окремо для pan і tilt, у градусах, де `targetAngle` — кут точки наведення в повному кадрі (розділ 4).

Спрощення: у симуляції кут цілі вимірюється в нерухомій системі координат, тоді як реальна камера на платформі вимірює його відносно власного положення в момент знімання. Запізнення реальної системи моделюємо затримкою команди (7.3). У README це згадуємо.

### 7.2 PID (на кожну вісь)

- Вихід — команда кутової швидкості (°/с).
- Мертва зона: при `|error| < deadband` (за замовчуванням 0,7°) похибка вважається нульовою.
- Вихід обмежений `maxVel`.
- Захист від накопичення: інтеграл не накопичується, коли вихід у насиченні, і обмежений за модулем.
- Похідна рахується за вимірюванням (не за похибкою) і згладжується, щоб уникнути стрибків.
- PID оновлюється на кожен новий результат детекції з фактичним `dt`. Між результатами діє остання команда.
- У станах `lost` і `returning` інтеграл скидається.

### 7.3 Модель сервоприводу

- Команда швидкості проходить через **затримку** (за замовчуванням 60 мс, налаштовується).
- **Обмеження прискорення** (за замовчуванням 600°/с²) і **швидкості** (за замовчуванням 180°/с; реальний SG90 без навантаження швидший, але з камерою на платформі це реалістичне значення).
- **Жорсткі межі кутів:** при досягненні межі швидкість по цій осі обнуляється.
- Симуляція рахується фіксованим кроком 5 мс (200 Гц) незалежно від частоти кадрів: у головному циклі накопичуємо `dt` і робимо потрібну кількість кроків.

### 7.4 Пресети

| Пресет | Призначення |
|---|---|
| «Добре налаштований» | Швидке встановлення без помітного перерегулювання |
| «Повільний» | Малий Kp: ціль помітно «втікає» від центру |
| «Розгойдується» | Великий Kp без D: видно перерегулювання і коливання |

Початкові коефіцієнти підбираються під час реалізації. Критерії задає інтеграційний тест (розділ 10).

### 7.5 Ручний режим

- Стрілки на клавіатурі задають швидкість (50% від `maxVel`) поки клавішу затиснуто.
- Повзунки pan/tilt задають цільовий кут, до якого платформа їде через простий P-регулятор.
- Перемикання Авто ↔ Ручний скидає інтеграл PID.

## 8. Інтерфейс

Розташування «Інженерний дашборд» (варіант A):

```
┌──────────────────────────────┬─────────────────────┐
│                              │ Вигляд з камери     │
│  Повний кадр                 ├─────────────────────┤
│  скелети + рамка поля зору   │ 3D-модель платформи │
├──────────────────────────────┼─────────────────────┤
│  Графіки: похибка і кути     │ Панель керування    │
└──────────────────────────────┴─────────────────────┘
```

**Повний кадр:** відео (дзеркальне відображення вимкнене, щоб напрямки збігалися з кутами), скелет цілі яскравим кольором, інші люди тьмяно, точка наведення, рамка поля зору, лінія від центру рамки до цілі. Клік по людині вибирає ціль.

**Вигляд з камери:** вирізане вікно, розтягнуте на панель, перехрестя в центрі, бейдж стану: «Пошук», «Супровід», «Ціль втрачено», «Повернення», «Ручний режим».

**3D-модель:** основа, вилка (pan), камера (tilt) і напівпрозорий конус поля зору. Вид обертається мишкою (OrbitControls).

**Графіки (вікно 10 с):** похибка pan/tilt (°) і кути pan/tilt (°), з лінією нуля й межами.

**Панель керування:**
- Перемикач Авто / Ручний
- Пресети регулятора
- «Розширені налаштування» (згорнуті): Kp/Ki/Kd, мертва зона, макс. швидкість, прискорення, затримка, `virtHfov`, `physHfov`, точка наведення (торс/голова), згладжування
- Показники: FPS відео, час детекції (мс), стан трекера
- Кнопка «Режим презентації»: ховає панель керування і розширені налаштування, решта панелей займає більше місця

**Стани та помилки:**
- Модель завантажується → індикатор з прогресом.
- Немає дозволу на камеру або камери немає → пояснення і кнопка «Спробувати ще раз».
- GPU-делегат недоступний → тихий відкат на CPU, у показниках позначка «CPU».
- У кадрі нікого → підказка «Станьте перед камерою».
- Браузер без потрібних API → повідомлення з рекомендацією Chrome.

## 9. Протокол для реального заліза (лише документація в README)

Цільове залізо: ESP32, драйвер PCA9685 (або прямий PWM), два сервоприводи (pan, tilt), USB-serial 115200 бод, текстові рядки, що закінчуються `\n`.

Хост → ESP32:
- `A <pan> <tilt>` — абсолютні цільові кути в градусах, точність 0,1, частота ~50 Гц
- `H` — повернення в нуль
- `?` — запит стану

ESP32 → хост:
- `S <pan> <tilt>` — поточні кути (у відповідь на `?` і періодично)
- `E <code>` — помилка

Безпека: якщо команди не надходять 500 мс, ESP32 тримає поточну позицію. Межі кутів дублюються в прошивці.

`SerialGimbalDriver` інтегрує команду швидкості у цільовий кут і надсилає `A` з частотою 50 Гц. Решта коду не змінюється.

## 10. Тестування

Vitest, тільки чиста логіка:
- `geometry`: пікселі ↔ кути взаємно обернені. Вікно на граничних кутах не виходить за кадр. Межі pan/tilt для 70°/35° 16:9 відповідають розрахунку.
- `pid`: мертва зона, обмеження виходу, захист від накопичення (інтеграл не росте в насиченні), скидання.
- `servoModel`: швидкість і прискорення не перевищують межі, кути не виходять за межі, затримка зсуває реакцію на заданий час.
- `targetTracker`: захоплення найближчої до центру людини, утримання при русі в межах воріт, `lost` → `returning` після 1,5 с, повторне захоплення, ручний вибір.
- `closedLoop` (інтеграційний, без камери): синтетична ціль, `SimGimbalDriver` і PID з однаковою затримкою.
  - Пресет «Добре налаштований»: стрибок цілі на 10° встановлюється в межах ±1° за ≤ 1 с, перерегулювання ≤ 15%. Синусоїда (амплітуда 10°, 0,2 Гц) після 2 с має середньоквадратичну похибку ≤ 2°.
  - Пресет «Розгойдується»: перерегулювання на тому самому стрибку ≥ 30%.
  - Пресет «Повільний»: час встановлення на стрибку ≥ 2 с.

Інтерфейс, камера і детекція перевіряються вручну.
